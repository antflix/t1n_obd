## Implemented repairs

- The local 1.10.25 repair branch had lost the remote 1.10.24 chunked streamer. Restored streaming and hardened its allocation behavior with a fixed buffer and correct control-byte escaping. Preserved the existing sensor catalogue and presentation fields; added canonical module ID, sample age and source uptime.
- Closed automatic-owner bypasses on legacy raw/DTC and physical probe routes. Explicitly paused/disconnected mode is required for firmware/SD maintenance; an empty/rejected firmware upload cannot reboot the scanner.
- Kept verified transport initialization, GPIO assignments, post-request poll pause, retry policy and disabled ABS qualification gate. Added request duration/failure, heap, reset, module-switch and last-persisted-sample telemetry. K-line idle LOW observations are not promoted to electrically qualified ignition sensing.
- Bounded debug text allocations to 16 KiB raw and 8 KiB activity tails, down from the old roughly 60/50 KiB Strings. Existing debug viewing/export remains; fewer old debug lines are retained. SD sensor history is unaffected.
- Preserved the three 32-byte journal formats and existing FNV-1a checksum (historically called CRC, but **not a polynomial CRC**). Recovery skips corrupt records. Interrupted partial append tails are overwritten at aligned offsets. Open/short-write errors count and back off. Repeated history ticks no longer multiply a source sample's aggregate count. Unwritten day/quarter data is retained on a write failure; stable quarters are recorded rather than suppressed for four hours.
- History uses bounded 200-record pages and a timestamp/tier/serial continuation cursor. SD scans run between diagnostic work, up to 128 records or a 2 ms soft budget per loop; reads are not serviced recursively inside UART receive loops. A physical SD operation can still exceed that budget. The UI recognizes pending/busy responses. Disjoint tier windows remove overlapping recent/quarter plotting. All-retained queries remain readable when current UTC is unknown.
- Shared history client, schema validation, error handling, age/alignment logic and CSV generation for mobile/Pi/fallback. Charts use SD records, source UTC, gap breaks, points, and min/max bars. No browser measurement-history store or failure fallback. Mobile chart selection survives scheduler module rotation. Multi-unit axes/legends and up to eight actual/target series remain. CSV includes module ID/label, sensor ID/label, unit, avg/min/max, count and tier. SVG export remains. Pi has all five ranges and System screen. Mobile has sensor search, larger touch controls and compact chart coordinates.
- Added ESP32-owned configurable coolant/oil, charging voltage, rail deficit and boost-error rules. Defaults disabled; no vehicle-specific limits are asserted. Monotonic debounce, hysteresis, running-context and fresh/aligned pair checks, severity, acknowledgment and recovery. Alert state persists in NVS and events on SD. A 16-entry NVS outbox retains transitions through SD failure/reboot. Stable event serials allow deduplication after an interrupted commit (at-least-once event delivery). Queue saturation/NVS/storage errors are exposed, never an all-clear.
- Added read-only saved DTC snapshot/event APIs preserving BASELINE/NEW/STATUS_CHANGED/NOT_REPORTED, raw statuses and unsupported/unknown distinctions. No undocumented diagnostic commands added.
- Kiosk deliverable uses a dedicated Chromium profile, single-process lock, local offline splash and bounded read-only reconnect supervision. No backend or measurement database. It has not been installed on the Pi.
- SD packaging now includes Pi and hashes all three HTML assets. Provisioning validates the full bundle before writes, defaults to inspection, requires explicit maintenance flags and paused monitoring, backs up existing pages and verifies mobile/Pi readback. It never changes monitor mode itself.
